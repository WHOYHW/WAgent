# 校园智能体（湖南理工大学）设计文档集

> 一个面向高校真实业务场景的 Agent 落地设计。核心不是"做一个聊天机器人"，而是**把高校的业务流程拆开，判断哪些环节可以交给 AI，哪些环节必须由人兜底，并给出可工程化的实现方案**。

---

## 一、项目要解决的真问题

高校信息化建设二十年，沉淀了教务、图书馆、一卡通、学工、后勤等一批**彼此独立的业务系统**。对学生的直接体验是：

- 想查课表要开教务系统，想查借阅要开图书馆公众号，想查成绩要等教务系统开放——**入口分散，重复登录**；
- 补考报名、选课开放、借阅逾期、成绩发布这些**有严格时间窗口的事**，通知躺在各自的系统里没人看，错过就是真损失；
- 真正复杂的事（成绩复核、学籍异动、奖助学金评定）流程长、跨部门、必须线下签字盖章，但学生**不知道找谁、要带什么材料、走到哪一步了**。

这个项目要做的是：**用 Agent 承接"高频、低风险、规则明确"的信息类与提醒类业务，把复杂业务的"前期准备"做掉，把最终决策与签章留给人和制度。**

## 四、关键设计约定

1. **只读优先。** 阶段一除"图书续借"外不引入任何写操作。凡涉及学籍、成绩、毕业结论的动作，Agent 一律不落库、不裁定。
2. **权威性可追溯。** 所有查询结果强制携带「数据来源系统 + 数据同步时间」，与源系统冲突时以源系统为准，Agent 不做二次推断。
3. **边界显性化。** 每个环节都必须在文档中标注 `AI`（可自动）/ `AI+H`（AI 准备 + 人工确认）/ `H`（禁止 AI 介入），不允许存在"说不清谁负责"的灰色环节。
4. **不做未授权抓取。** 数据接入优先级为：学校开放接口 / 数据中台只读视图 > 与信息中心共建适配器 > 学生本人授权后的个人数据接口。**不采用绕过统一身份认证的爬取方案。**

## 五、术语表

| 术语 | 说明 |
|---|---|
| 教务系统 | 承担排课、选课、成绩、学籍的校级系统，常见厂商：正方、强智、超星等 |
| ILS | 图书馆集成管理系统（Integrated Library System），常见：汇文、图创 Interlib；对外协议 SIP2 / Z39.50 / OPAC |
| 一卡通 | 校园卡系统，承载消费、门禁、图书借阅、水电等身份与支付能力 |
| 统一身份认证 | 校级 SSO，通常基于 CAS 或 OAuth2，账号为学号 |
| 第二课堂 | 课外素质拓展学分体系，与第一课堂学分共同构成毕业要求 |
| 学籍异动 | 休学、复学、转专业、退学等学籍状态变更 |
| 人培方案 | 人才培养方案，规定专业毕业所需的课程与学分结构 |
