## 一、范围与动机

**现状**：229 个测试函数（18 个文件）已全部内存化、零网络可跑，但只在开发者本机存在——没有任何机器在每次提交时强制它们通过；分层架构（12）与 D1「否决 APScheduler」（09）只活在文档里，代码层面一次跑偏就能悄悄发生。

**本任务交付三件护栏**（对标 DeepInfer 推理框架的工程实践：ruff TID251 禁用清单 + CI 测试分层）：

| 交付物 | 强制什么 | 章节 |
|---|---|---|
| ruff（linter） | 代码风格基线 + 第三方依赖禁用清单（TID251） | §三 |
| import-linter（导入契约） | 分层单向依赖 + 提醒引擎/编排层互不依赖 | §四 |
| GitHub Actions（CI） | 每次提交：lint → 契约 → 229 项测试全绿 | §五 |

**不在范围**：`ruff format`（见 D1）、评测黄金集（任务 17，将复用同一条 CI 管线）、覆盖率门禁（pytest-cov 已在 dev 依赖，阈值待黄金集落地后定）。

## 二、决策点裁决

| # | 裁决 | 备选与理由 |
|---|---|---|
| D1 | **只上 linter，不上 formatter**（`ruff check`，不跑 `ruff format`） | 代码为手工排版：中文注释对齐、参数竖排等格式承载可读性语义，全量格式化会产生数千行不可 review 的 diff。formatter 待团队成规模后单独 `style:` 提交一次到位 |
| D2 | **TID251 管第三方包、import-linter 管模块分层**，互补不重叠 | ruff 的 TID251 只能禁到「包」粒度（apscheduler/requests），模块间分层（reminder 不得 import orchestrator）它管不了；import-linter 恰好只管这个。两者拼起来才是完整依赖护栏 |
| D3 | **E501 首轮关闭**（line-length 仍设 120） | 实测现存最长行 338 字符（orchestrator.py 长注释）；中文按字符计宽与阅读宽度不成比例，首轮开 E501 的噪音会淹没真问题。随 D1 的 formatter 决策一并处理 |
| D4 | **CI 单版本 Python 3.13，不做矩阵** | requirements 声明 3.13+；单仓库单人阶段矩阵是纯成本。升 3.14 基线时改一行 |

## 三、ruff 定版（backend/pyproject.toml）

新建 `backend/pyproject.toml`（与 `pytest.ini` 并存——测试配置零变更，本任务不碰它）：

```toml
[tool.ruff]
line-length = 120
target-version = "py313"
include = ["app/**/*.py", "tests/**/*.py", "*.py"]

[tool.ruff.lint]
select = ["E", "F", "W", "I", "UP", "B", "SIM", "TID251"]
ignore = [
    "E501",  # D3：现存长注释（最长 338 字符）噪音淹没真问题，随 formatter 决策一并处理
]

[tool.ruff.lint.flake8-tidy-imports.banned-api]
"apscheduler".msg = "09 §D1 裁决：心跳用进程内 asyncio，禁 APScheduler。"
"requests".msg = "HTTP 统一走 httpx（adapters/base.py 契约）。"

[tool.ruff.lint.per-file-ignores]
"tests/*" = ["E402"]  # conftest.py 的 sys.path 注入先于 app 导入
```

规则选型说明：

| 规则组 | 作用 | 备注 |
|---|---|---|
| E/F/W | pycodestyle + Pyflakes 基线 | 未用导入、明显笔误 |
| I | import 排序 | 与现有「stdlib → 相对导入」分区习惯一致 |
| UP | pyupgrade | `str | None` 等现代写法已是项目惯例，UP 只补漏 |
| B/SIM | bugbear + simplify | 常见逻辑坑（可变默认参数、冗余分支等） |
| TID251 | 禁用依赖清单 | 裁决机器化的落点，见 banned-api |

**首轮执行预期**：违规主要集中在未用导入与 import 排序，逐条修复；确属误伤的用行内 `# noqa: XXX` + 中文理由，**禁止文件级豁免**。

## 四、导入契约定版（import-linter，同文件追加）

分层依据为 **2026-10-29 实测依赖图**（grep 全量相对导入），不是文档 12 的理想图——契约先咬住现实，再随重构收紧：

```toml
[tool.importlinter]
root_packages = ["app"]

[[tool.importlinter.contracts]]
name = "提醒引擎与编排层互不依赖（09 §2.1）"
type = "independence"
modules = ["app.reminder", "app.orchestrator"]

[[tool.importlinter.contracts]]
name = "主链路分层单向（12 分层架构机器化）"
type = "layers"
layers = [
    "app.main",        # 顶层装配，唯一允许 import 一切的位置
    "app.llm",         # 仅依赖 orchestrator 的冻结协议（03 §2.4）
    "app.orchestrator",
    "app.reminder",
    "app.tools",
    "app.conversation",
    "app.adapters",
    "app.guardrail", "app.stale", "app.degrade", "app.logging_util",
    "app.db", "app.security", "app.cache",
    "app.orm", "app.schemas", "app.config", "app.cache_redis",
]
```

实测依据（关键边）：

| 层 | 实际 import（2026-10-29 grep） | 与契约关系 |
|---|---|---|
| llm → orchestrator | `LLMClient` 协议类型 | llm 必须在 orchestrator 之上（仅协议依赖） |
| orchestrator → tools/conversation/guardrail/logging_util/security/schemas/config | 全量实测 | 不 import reminder/adapters/llm ✓ |
| reminder → adapters/orm/logging_util/config/security/schemas | 全量实测 | 不 import orchestrator/tools/conversation ✓ |
| tools → adapters/cache/degrade/stale/security/orm/logging_util/config/schemas | 全量实测 | 不 import conversation/reminder ✓ |
| logging_util → orm/security | 审计落库 + 脱敏 | 故位于 orm/security 之上 |
| cache → cache_redis | 后端切换 | 同层不得互导，cache 高一层 |

**未入约模块**：`app.nlu`（空占位）、`app.ve`（空目录）、backend 根的 `demo_orchestrator.py` / `export_schemas.py`（app 包外，不受 root_packages 约束）。它们产生真实代码时随迁移修订本契约。

## 五、CI 管线定版（.github/workflows/ci.yml）

```yaml
name: ci
on:
  push: { branches: [dev, master] }
  pull_request: { branches: [dev, master] }
jobs:
  test:
    runs-on: ubuntu-latest
    defaults: { run: { working-directory: backend } }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"
          cache: pip
          cache-dependency-path: backend/requirements*.txt
      - run: pip install -r requirements.txt -r requirements-dev.txt
      - run: ruff check .
      - run: lint-imports
      - run: pytest
```

- **触发面**：dev（日常）+ master（合并），PR 双向；
- **`--live` 不受影响**：真机联调测试沿用 05/07 的显式 opt-in 惯例，默认跳过，CI 天然不触网；
- **首跑预期**：Linux 首跑可能暴露路径/时区平台差异（如 SQLite 相对路径、CAMPUS_TZ）——当场修复，这本身就是 CI 的第一批收益；
- **分支保护**：仓库设置 master 的 PR 必须过 `ci` 才可合并（dev 为日常分支，仅要求触发）。
