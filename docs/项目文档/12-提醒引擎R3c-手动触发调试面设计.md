# 提醒引擎 R3c — 手动触发调试面（实施设计）

> 上游：09-提醒引擎设计 §F1 / §2.6；前置：10（R3a 心跳骨架）、11（R3b 求值器接线）。
> 本切片范围：为 `scan_once()` 增加一个 HTTP 手动触发入口，联调与 R7 验收不再等待心跳 tick（默认 300 s）。

## 一、需求与定位

心跳 `_loop` 的触发节奏是 `reminder_scan_interval_seconds`（默认 300 s）。联调阶段每改一次求值器逻辑都要等几分钟才能观察一轮扫描，R7 端到端验收也需要一个**可点击、可断言**的触发入口。为此增加一个同步调试端点：

```
POST /agent/reminders/scan
→ 同步执行一次 _reminder_engine.scan_once()
→ 返回 ScanStats（JSON）
```

**边界**：本端点是调试/运维面，不进 `/tools` 工具注册表（不是学生可用的"工具"，不让 LLM 决定是否调用）；SSE 对话路径不感知它的存在。

## 二、设计决策（定版）

### D1 路径命名：`/agent/reminders/scan`（复数）

任务指定复数形式。与既有 `/agent/reminder/subscribe`（单数）存在命名不一致——**登记为已知债务**（R4 引入 dispatch 端点时统一评审），本切片不擅改既有端点路径（避免破坏已交付的 API 契约）。

### D2 鉴权：复用 `get_current_student`，但令牌身份 ≠ 数据范围

- 无令牌 → 401（与全部 `/agent/*` 端点一致，不提供匿名触发面）；
- **关键语义**：`scan_once()` 是**全局对账**——扫所有学生的 enabled 订阅，不按令牌身份过滤。令牌在这里只负责"给入口上锁"，防止匿名/外网触发，**不实现按学生隔离**（学生隔离发生在求值器内部的源快照层，见 11 §2.4）。
- 触发者身份记入日志：`reminder_scan_manual` 事件 + `mask_student_id` 脱敏（R3 敏感数据红线：学号不落明文日志）。

### D3 不受 `reminder_enabled` 门控

`reminder_enabled=False` 时心跳不启动（AC-1a），但 **`scan_once()` 本身不检查该开关**——这正是设计意图：联调场景心跳通常关着，手动触发是唯一的执行通道。端点在日志里带上 `reminder_enabled` 当前值，方便区分"手动扫了一次"与"心跳在跑"两种状态。

### D4 ScanStats 序列化：`to_dict()` 放在数据类上

序列化逻辑写进 `ScanStats.to_dict()`（`datetime` → `isoformat()`，`duration_ms` 走既有 property），而不是端点内联拼 dict。理由：① 可单测；② R4 的 dispatch 消费端（推送下发记录扫描结果）大概率复用同一形状。

### D5 并发语义：手动触发与心跳可能并发两轮扫描

D1 裁决（09 §三）"调度器应当愚蠢，正确性交给数据库"：幂等性由 R4 的 claim / dedup_key 落地后兜底。R3 阶段 `scan_once` **纯读零写副作用**（产出候选后即丢弃，不落库、不推送），并发双扫无实际危害——登记为 R4 验收检查项（AC：手动 + 心跳并发两轮，dedup 不产生重复下发）。

## 三、接口契约

### 请求

```
POST /agent/reminders/scan
Authorization: Bearer <token>
（无请求体）
```

### 响应（200）

```json
{
  "started_at": "2026-10-27T08:00:00.123456+00:00",
  "finished_at": "2026-10-27T08:00:00.456789+00:00",
  "subscriptions": 3,
  "candidates": 1,
  "evaluator_errors": 0,
  "scan_errors": 0,
  "duration_ms": 333
}
```

### 错误

| 状态码 | 条件 |
|---|---|
| 401 | 缺失/无效令牌（`get_current_student`） |
| 500 | 不可能出现——`scan_once` 全捕获普通异常，永不抛出（R3a 不变量），失败以 `scan_errors > 0` 体现在 200 响应里 |

## 五、测试计划（AC-3）

| 编号 | 验收点 | 手段 |
|---|---|---|
| AC-3a | 无令牌 → 401，且真实引擎未被触碰 | ASGITransport + FakeEngine 调用计数 |
| AC-3b | 带令牌 → 200，响应字段与 FakeEngine 注入的统计逐字段一致，引擎恰被调用 1 次 | `app.main._reminder_engine` monkeypatch |
| AC-3c | 真实引擎端到端：内存库 seed 1 条 enabled + 1 条 disabled 订阅 → `subscriptions==1`、`candidates==0`（空求值器纯读空转）、`scan_errors==0` | 复用 test_reminder_engine 的 `seed_subscription` + 内存库夹具 |
| AC-3d | `ScanStats.to_dict()` 字段完备：7 键齐全，`finished_at=None` 时 `duration_ms=None` 且不抛异常 | 纯单测 |

分层原则：端点只测"装配 + 鉴权 + 序列化"；引擎内部逻辑已由 test_reminder_engine（14 例）、test_reminder_evaluator（19 例）覆盖，不重复。

## 六、已知限制（登记）

1. **路径命名不一致**：`reminders`（复数）vs `reminder/subscribe`（单数），R4 统一评审（D1）。
2. **并发双扫**：手动与心跳可同时跑两轮，R3 纯读无害，R4 落地 claim/dedup 后必须补并发验收（D5）。
3. **无请求参数**：不支持"只扫某学生/某 subject"的过滤——调试面保持最小表面，需要定向调试时直接跑 pytest 更快。
