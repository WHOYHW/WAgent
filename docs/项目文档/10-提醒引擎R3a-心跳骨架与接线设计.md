## 三、ReminderEngine（app/reminder/engine.py）

### 3.1 构造与求值器协议

```python
@runtime_checkable
class ReminderEvaluator(Protocol):
    subjects: AbstractSet[str]   # 认领的 subject 值集合（ORM 列是 str，鸭子类型）
    async def evaluate(self, subs: Sequence[Any], now: datetime) -> list[ReminderCandidate]: ...

class ReminderEngine:
    def __init__(self, session_factory, evaluators=(), settings=None, *, jitter_ratio=0.1): ...
```

- **session_factory 注入而非 import 全局**：`scan_once` 每次扫描开**独立**
  db 会话、用完即关，不与请求会话（`get_db` 依赖）共享；测试用内存 SQLite
  工厂注入，AC-1 的会话隔离由此结构性保证；
- ORM 订阅行在**会话关闭后**才交给求值器（列已加载，无懒加载风险），
  R3b 求值器内部使用自己的适配器/会话，职责边界干净。

### 3.2 start / stop：幂等，镜像 aclose 置空引用模式

| 场景 | 行为 |
|---|---|
| `start()`，`reminder_enabled=False` | 记 `reminder_disabled` info 日志，no-op（不建 task） |
| `start()`，已有存活 task | no-op（幂等） |
| `start()`，正常 | `asyncio.create_task(_loop, name="reminder-engine-heartbeat")` |
| `stop()`，task 为 None | no-op（幂等：未启动 / 已停） |
| `stop()`，正常 | 先置 `_task=None`（并发 stop 走 no-op）→ `cancel()` + `await`（suppress `CancelledError`） |

与 `BaseAdapter.aclose()` 同构：关闭后置空引用，允许再次 `start()` 重建——
shutdown 后的心跳**不会复活**（应用生命周期唯一），但单测/工具场景可重启。

### 3.3 _loop 与睡眠抖动

```
while True:
    await scan_once()          # 自身全捕获，永不抛出（见 3.4）
    await asyncio.sleep(_jittered_interval())
```

- `_jittered_interval() = interval × (1 ± jitter_ratio)`，默认 ±10%，
  下限 clamp 0.01s（防 `interval=0` 退化热循环）；
- **抖动理由**：多实例（uvicorn --workers>1）同刻启动会把 claim 碰撞集中在
  同一 tick；±随机化把碰撞摊薄。抖动只作用于"下次何时扫"，不影响窗口
  语义（horizon = 间隔 × 2 已容忍 tick 抖动，09 §2.3）；
- `CancelledError` 是 `_loop` 唯一退出路径——`except Exception` 在
  Python 3.8+ 不捕获它，cancel 可从 sleep 或 scan_once 内部任意 await 点打断。

### 3.4 scan_once：单测直调入口 + 两层异常捕获

```python
@dataclass
class ScanStats:
    started_at: datetime
    finished_at: datetime | None
    subscriptions: int      # enabled 订阅数（分发前计数）
    candidates: int         # 全部求值器产出候选总数
    evaluator_errors: int   # 求值器级异常（风险③第②层）
    scan_errors: int        # 会话/查询级异常（风险③第③层）
```

管线：**独立会话 → 查 enabled 订阅 → 按 `evaluator.subjects` 分发 →
逐求值器 try/except → 汇总 ScanStats**。异常分层（09 风险③）：

| 层 | 捕获范围 | 效果 |
|---|---|---|
| 求值器级（②） | 单个 `evaluate` 抛出（含 R3b 的 `CandidateGenerationError` 脏订阅） | 计 `evaluator_errors`，其余求值器与本 tick 继续 |
| 会话级（③） | 会话获取/查询抛出 | 计 `scan_errors`，返回全零 stats |

两层都不向外抛出——loop 层**无需**兜底重启逻辑（09 风险③的三层防线中，
第①层入库 validator 已随 R1 落地，本切片落②③）。

## 四、lifespan 三接线（main.py）

```
startup:  init_db(dev) → _reminder_engine.start()   # enabled=false 时内部 no-op
shutdown: _reminder_engine.stop() → edu/lib/LLM/push aclose
```

- **顺序约定：先停心跳再关适配器**——保证扫描停止后不再有适配器消费者；
- push 适配器单例 `aclose` 已在 R2 落地（保持原位），本次补齐 engine 两线；
- shutdown 侧收进 `try/finally`：任何一个 `aclose` 抛异常不阻断其余清理
  （心跳 stop 必达，AC-1 的"无悬挂任务"才可靠）。

## 五、AC-1 测试计划（tests/test_reminder_engine.py）

| 用例 | 断言 |
|---|---|
| AC-1a disabled 不启动 | `start()` 后 `engine._task is None`；`asyncio.all_tasks()` 无 heartbeat 任务 |
| AC-1b start 幂等 | 二次 `start()` 仍是同一 task，不新建 |
| AC-1c stop 幂等 + 可重启 | 未启动直接 stop 不抛；二次 stop 不抛；stop→start 重建新 task |
| AC-1d shutdown 无悬挂 | stop 后 task `cancelled()`；`asyncio.all_tasks()` 无 heartbeat 残留；`engine._task is None` |
| AC-1e 异常不杀心跳 | 求值器持续抛 / 会话工厂持续抛，`interval=0.05` → 多 tick 后仍在扫描，stop 收敛 |
| 管线正确性 | scan_once 拉订阅数正确；只把 enabled 且匹配 subject 的订阅喂给求值器；ScanStats 计数正确 |
| 抖动边界 | `_jittered_interval()` ∈ [0.9i, 1.1i]；`jitter_ratio=0` 恒等于 i；小间隔命中 0.01s 下限 |
