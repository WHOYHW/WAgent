## 一、范围

R3b 把 R3a 的"纯读空转"升级为**真实求值**：`LibraryDueEvaluator` /
`CourseEvaluator` 实现 R3a 定义的 `ReminderEvaluator` 协议，接线既有纯函数
（`due_library_candidates` / `due_course_candidates`，R1 交付）与既有适配器
（`LibAdapter.fetch_loans` / `EduAdapter.fetch_timetable`，降级语义白拿）。

**不做**：时机门四闸（R4）、claim/下发/终态（R4/R5）、weeks 周次匹配
（见 §六 已知限制）、并发拉取（见 §四）。

## 二、求值管线（两个求值器同构）

```
订阅（引擎已过滤 enabled）→ 按学生分组 → 逐学生：源快照（走适配器既有缓存）
  → 新鲜度裁决 → 逐订阅：喂纯函数 → 候选汇总
```

### 2.1 新鲜度裁决（AC-10）

快照进入纯函数前必须完成裁决：`degrade_status ∈ {FRESH, LIVE_OK}` 放行；
`STALE_CACHE` / `UNAVAILABLE` → 该学生**零候选** + `*_snapshot_degraded`
warning 日志（含脱敏学号与 degrade_status）。

依据（09 §2.3）：用陈旧缓存里的到期日推送"明天到期"是 P1 事故路径——
**宁可不发，不发错误数据（C4 R4.4）**。FRESH（缓存命中未过期）不是陈旧数据，
照常放行。

### 2.2 课表快照日规则（本设计定版）

`due_course_candidates` 消费"某一天的有效课节"，快照拉哪一天由订阅的
timing 粒度决定。**规则：`snapshot_date = 今天 + max(各时机提前量的天数部分)`**
（h/min 粒度记 0，纯函数内 `parse_timing` 换算）：

| timing 集合 | snapshot_date | 推导 |
|---|---|---|
| `{T-30min}` / `{T-2h}` | 今天 | T-30min 落窗的课必在 ~35min 内开课 ⇒ 必是今天的课 |
| `{T-1d}` | 明天 | 明天 8:00 的课，trigger = 今天 8:00 |
| `{T-3d}` | 今天+3 | 3 天后开的课，trigger = 今天同节次时刻 |
| 混合 `{T-3d, T-30min}` | 今天+3 | 取最大提前量；混合集合的 h/min 时机在远日快照下不命中窗口——**有意取舍**（升级方向：按时机分组取多个快照） |

同一学生的多个订阅按 `snapshot_date` 分组后共用一次拉取（缓存 key 含日期，
天然去重）。

### 2.3 隔离粒度（对齐"按学生隔离"评审意见并细化）

| 故障 | 隔离粒度 | 理由 |
|---|---|---|
| 源快照失败（异常 / degraded） | **学生** | 快照是学生级所有权：A 的源挂了没有理由让 B 拿不到候选 |
| 脏数据（`CandidateGenerationError`：脏 trigger_config / 节次映射缺失） | **订阅** | 09 v1.3 原文"单点毒不扩散"；跳过该订阅，同学生其余订阅继续 |

两层都只记日志（`*_snapshot_failed` / `*_sub_skipped`，学号脱敏），
**不向上抛出**——单学生故障不杀整轮扫描。

### 2.4 校园时区常量（新定版，供 R4 复用）

```python
CAMPUS_TZ = timezone(timedelta(hours=8), name="Asia/Shanghai")
```

- `due_course_candidates` 用 `now.tzinfo` 组合"节次开课时刻"（8:00 = 第 1 节），
  引擎传入的 `now` 是 UTC——直接用会把 8:00 的课当成 UTC 8:00（= 北京 16:00），
  **相对日期全部漂移**；求值器入口统一 `now.astimezone(CAMPUS_TZ)` 后再喂纯函数，
  绝对时刻比对跨时区天然正确，`dedup_date` 回归校园日历日；
- 固定 +8 偏移而非 `ZoneInfo`：中国无夏令时，免 tzdata 依赖（零新依赖约束）；
- 09 风险⑤单时区假设（服务器在校内）的直接落点；R4 静默门（本地时 23:00–07:00）
  消费同一常量，保证"开课时刻 / 静默窗口 / dedup_date"三处时区同源。

## 三、纯函数小重构（candidates.py）

`_sub_timings` 升为公开 `subscription_timings(sub, subject_value)`（行为不变，
含 TriggerConfig 校验 + 目录默认回退）：求值器需要用同一来源读订阅的
timing 集合（快照日规则 + 脏数据同一报错路径），禁止第二份实现（R1.1 同源精神）。

## 四、lifespan 接线（main.py）

```python
_reminder_evaluators = (
    LibraryDueEvaluator(lib=_shared_services.lib, settings=settings),
    CourseEvaluator(edu=_shared_services.edu, settings=settings),
)
_reminder_engine = ReminderEngine(async_session_factory, evaluators=_reminder_evaluators, ...)
```

求值器共享进程级适配器单例（缓存/连接池复用）；**源调用串行**（阶段一订阅量小，
日扫描量 ≤ 订阅数/300s，串行足够；并发拉取登记为阶段二优化——asyncio.gather
按学生分组即可，接口无需改动）。

## 五、测试计划（tests/test_reminder_evaluator.py）

| 用例 | 断言 |
|---|---|
| AC-2 窗口命中 | 借阅 T-3d/T-1d 各恰一候选；`dedup_date = trigger_at.date()`；超期借阅不产出 |
| AC-10 降级不出错数据 | stale_cache / unavailable → 零候选；FRESH / LIVE_OK 正常产出 |
| 快照日规则 | `{T-30min}`→今天、`{T-1d}`→明天、`{T-3d}`→今天+3（断言适配器收到的 start/end_date） |
| 按学生隔离 | A 生源故障 / degraded，B 生照常产出 |
| 按订阅隔离 | 同学生一脏订阅被跳过，其余订阅产出 |
| 已开课抑制 | 课已开（start ≤ now）不产出 |
| 引擎端到端 | scan_once 经 DB 订阅 → 求值器 → ScanStats.candidates 计数正确 |
